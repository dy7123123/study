# 定时任务设计文档：活动状态自动更新任务

## 一、功能概述

本定时任务用于定期扫描邀请有礼活动的状态，根据系统时间自动更新其状态，确保活动流程符合预期，从而减少人为操作，提高系统智能化程度。

## 二、活动的状态

活动在创建成功后会进入状态流转流程，包括：

- `NEW（1）`：创建成功，未启用
- `VALID（2）`：活动已启用，尚未开始
- `IN_PROGRESS（3）`：活动进行中
- `FINISH（4）`：活动已结束
- `TERMINATION（5）`：活动已终止（手动）



实现一个定时任务，每分钟执行一次，自动更新活动状态：

- `VALID` → `IN_PROGRESS`：当前时间 >= 活动开始时间
- `IN_PROGRESS` → `FINISH`：当前时间 > 活动结束时间

部分状态依赖系统时间推进，如活动的开始时间、结束时间。因此需实现一个定时任务来自动更新状态。

## 三、功能实现

- **任务名称**：活动状态自动更新任务（JobHandler 名称：updateActivityStatusJob）
- **执行周期**：由 XXL-JOB 调度中心配置，设置为每分钟执行一次 （Cron ：0 */1 * * * ?）
- **技术方式**：任务执行入口使用 XXL-JOB 提供的注解 @XxlJob("updateActivityStatusJob") 
- 
```java
@XxlJob("updateActivityStatusJob") 
```
- **需要的接口**：InteractActivityService
- 需要提供根据当前活动状态查询活动列表的接口
- 更新活动状态的接口
```java
List<InteractActivity> getActivitiesByStatus(Integer status);
void updateActivity(InteractActivity activity);
```
- **实现逻辑**：
  - 1. 查询活动状态为 `VALID` 和 `IN_PROGRESS` 的活动列表
    - 1.1 `VALID`：当前时间 >= 活动开始时间
    - 1.2 `IN_PROGRESS`：当前时间 > 活动结束时间
  - 2. 遍历活动列表
    - 2.1 如果活动状态为 `VALID`，且当前时间 >= 活动开始时间，则更新状态为 `IN_PROGRESS`
    - 2.2 如果活动状态为 `IN_PROGRESS`，且当前时间 > 活动结束时间，则更新状态为 `FINISH`
  - 3. 更新活动状态

- **日志和异常处理**：使用 XxlJobHelper.log() 记录任务执行的关键步骤和时间点
